## 1. 交付目标

在新项目内实现独立示例，参考现有 `lyrics-ui` 示例的播放器页面布局和操作方式，展示 `FoliaLyricsView` 的实际接入。开发者能够运行示例、替换歌词数据、提供播放快照，并观察暂停、跳转和配置变更的行为。

示例是首版交付内容，不能仅用 Compose Preview、静态截图或无交互的测试页代替。首版需要 Android 应用和 Windows x64 Desktop 应用；两者共用页面、演示数据与时钟逻辑。

现有 Apache-2.0 工程只读参考。新示例、资源、配置、构建和运行说明全部保存在 `lyrics-ui-folia` 项目，不向原工程增加任何 Folia 代码或依赖。项目分离用于明确工程与发布边界；许可选择及适用范围继续按主设计的来源核对流程确认。

## 4. 页面布局

### 4.1 窄屏

初始断点参考原示例的 600dp，后续以实际内容容纳情况校准。布局从上到下为：

1. 系统安全区；顶部横排放 72dp 封面、标题／作者，以及翻译、注音、更多按钮。
2. 占据剩余主要空间的歌词舞台，调用 `FoliaLyricsView`，不在其外部叠加原歌词列表的锚点和渐隐。
3. 底部播放区：进度条、当前／总时间、播放／暂停、重播、倍速与循环入口。

参考顶部水平边距 28dp、歌词外边距 12dp；小屏、横屏和大字体下优先给文字留下可用区域，工具溢出进入菜单，不能依靠固定大高度挤压歌词到零。设置使用可滚动的底部面板，开发诊断默认折叠。

### 4.2 宽屏

采用左右两栏：左栏约占 40%，放大封面、曲目信息与播放控制；右栏为歌词舞台。参考原示例的封面／元数据层次，但不照搬 100dp 固定左边距；按窗口可用尺寸限制封面最大值及留白。

设置默认以对话框打开。调试时可打开侧面板；面板占用的宽度必须进入歌词组件约束并触发布局更新，不覆盖文字后仍按原宽度计算。窗口变窄时切回窄屏结构，保持当前曲目、位置和设置。

默认背景为低对比静态渐变，封面使用自制占位图。背景只属于示例壳，并提供纯色模式供截图与性能测试使用；不把背景引擎加入库 API。

### 4.3 状态与文案

首次启动进入待选歌页。“选择歌曲”需要音频，歌词/翻译可选；确认后真实播放，
显示可获取元数据和真实时长。取消/失败保留原会话。合成场景仅在“开发／演示”入口，
明确显示“演示时钟 · 无音频”，不推动真实播放路径。

无歌词时仍播放并显示“未加载歌词”，提供“补选歌词／翻译”。在位应用不换播放器、
不跳转；导入失败保留原歌词并报告错误。有限前奏/间奏等待球依据全声部区间并集，
不把无歌词、错误、加载或歌曲结束当作等待区间。旧演示控制只属于开发入口。

## 5. 播放与组件接入

### 5.1 共享控制器

真实音频由sample的LocalAudioPlayer/SongSession提供快照：Android使用MediaPlayer，
Desktop使用Java Sound Clip；直接读取原生游标，不同时启动PreviewPlaybackController。
开发/演示才使用下述PreviewPlaybackController，拥有当前媒体位置、总时长、播放状态、
速度、循环设置与discontinuity。两个路径都不把播放器类型带入库公共API。

演示位置通过单调时钟计算：

```text
playingPosition = anchorPosition + (monotonicNow - anchorTime) × speed
pausedPosition  = anchorPosition
```

结果约束在当前场景允许的范围内。播放／暂停或速度改变时，先按旧状态计算当前位置，再重设锚点，避免进度跳跃。快照位置已包含速度，传给库后不再次乘倍速。

控制器在播放且页面可见时按帧更新可观察的 `FoliaPlaybackSnapshot`，页面不可见后暂停演示并停止调度；返回时保持暂停位置。Android Activity 重建或 Desktop 调整窗口大小不能意外创建第二个时钟。控制器释放时取消任务。

每次 seek、重播、循环回绕和内容切换都增加 discontinuity；普通顺序更新、暂停／恢复及连续变速不增加。进度条松手、歌词点击和快捷键统一进入同一 seek 方法，不能各自维护位置。

### 5.2 UI 状态与连接点

低频 UI 状态保存当前场景、元数据、加载结果、设置和面板开关；高频位置单独暴露。页面根节点不按每帧位置重组。进度文本按秒展示，进度条和歌词各自读取其需要的状态。

歌词区域的唯一入口是主设计定义的 `FoliaLyricsView`：

- `lyrics` 传入原始 `SyncedLyrics`，不提前改写时间或展开成字符串列表。
- `playback` 使用稳定 lambda，一次返回同一份可观察快照。
- `contentKey` 使用场景 ID 加数据修订号；切换样本或重载内容时变更，不能因每帧位置更新而变化。
- 配置切换使用 typography／options／annotations 等已实现契约，不添加只在示例中有效的伪参数。
- `onLineClicked` 按来源行的 start seek；开启歌词偏移后，按主设计约定将歌词时间换回媒体时间，并约束到合法范围。
- `onLinePressed` 打开当前来源行信息面板，不引入原应用的分享服务，也不默认输出整首用户歌词到日志。

增加一份最小接入代码，展示模型、快照和回调即可；不能要求使用方复制整个 sample controller 才能调用组件。

### 5.3 操作约定

| 操作 | 结果 |
| --- | --- |
| 播放／暂停 | 同步更新快照；暂停后正文及媒体驱动动效冻结 |
| 进度拖动 | 显示待提交时间，保留原播放状态；松手提交一次，取消则丢弃预览 |
| 点击当前歌词 | 跳到来源行开始，保持原播放／暂停状态 |
| 切换场景 | 原子替换内容与时长，位置归零、暂停、更新 contentKey 和 discontinuity |
| 0.5／1／1.5／2 倍速 | 连续位置上改变速度，不触发双倍计算 |
| 重播 | seek 到起点，保留原播放／暂停状态 |
| 开启循环 | 到末尾回到起点并继续播放；关闭时到末尾停住 |
| 暂停步进 | 调试面板提供前后 16ms、跳到选定检查点，均走统一 seek |

Desktop 首版快捷键：Space 播放／暂停，左右方向键前后 5 秒，Ctrl+O 打开歌词，Ctrl+R 重载已导入歌词，Esc 关闭当前面板。仅在应用前台且焦点不在文本输入、进度条或其他消费该按键的控件上处理；按钮仍需能完成全部操作。

## 6. 场景、导入与音频边界

### 6.1 默认内置场景

采用自行编写、允许分发的合成文本及确定性时间，不附带商业歌曲、原项目封面或未知授权字体。每个场景具备唯一 ID、标题、时长、构造数据和检查点清单。

| 场景 | 主要验证 |
| --- | --- |
| 基础中英混排 | classic 主句、词高亮、翻译、注音和下一句 |
| 极短行／密集切换 | Micro／Short 边界、重叠退场与 seek |
| 长音／长句 | 换行、fit、辉光余韵和视觉边界 |
| 前奏／空档 | 无活动行、等待提示和末尾停止 |
| 重叠主唱／伴唱 | 主句选择、次声部、来源行点击 |
| Unicode | 组合字符、ZWJ emoji、RTL 与复杂 shaping；缺字时记录字体环境 |
| 仅行时间 | 显式展示行级或派生计时模式，不标成真实逐字时间 |
| 300 单元压力句 | 缓存、降级和可选计算后端对照，标明压力样本 |
| 空／异常数据 | 手动选择的诊断场景，不影响默认可用路径 |

只有库实际支持的输入形式才进入正常演示；未支持项应明确注明。场景中的字幕／注音字段通过主设计指定的 core 映射与 annotations 输入，不为方便 sample 修改 core 或原 UI。

### 6.2 本地歌词导入

首版允许用户选择单个本地歌词文件，并以演示时钟预览。P0 核对所锁定 `lyrics-core` 的真实解析 API，先交付已验证的 LRC／逐词格式；文件选择器和 README 列出实际支持扩展名，不照抄原应用全部格式承诺。

Android 使用用户选择的文档 URI；Desktop 使用用户选择的路径。解析在后台执行，完成后原子提交；连续导入时丢弃过时结果。取消选择不改变当前内容。解析错误说明原因，不能静默替换为内置数据。时长按歌词最后有效结束时间与配置的尾段余量计算，并可在调试设置覆盖。

偏好与导入历史使用本示例自己的应用标识和目录，例如 `LyricsUiFoliaSample`；不读写原应用配置。重启后 URI／文件不可访问则回到内置场景并提示重新选择。只为用户选择的文件取得所需访问能力，不复用原示例的整盘访问申请流程。

### 6.3 真实音频

首版验收以无音频演示和本地歌词导入为准。需要真实音频时，后续通过示例内独立平台播放器适配器提供同一快照与 seek 接口，音频 SDK 只能属于 sample 平台模块。不能把播放器、音频资源或外部进程接入作为歌词库与默认示例的前置条件。

## 7. 设置与诊断

普通设置提供翻译、注音、下一句、字号、画质、减少动态效果，以及 `classic` 已实现的旋转、呼吸、词间距和避免重叠选项。首版样式仅 classic，不展示不可用的后续样式按钮。

开发面板默认关闭，集中显示场景 ID、精确时间、discontinuity、当前来源行、可见单元数量、准备状态、实际画质和已提供的耗时统计。不能把瞬时 FPS 当作完整性能结论，不能为面板本身引入逐帧全屏重组。

native 相关信息必须区分“请求后端”和“实际后端”。未安装、未构建或未通过平台验证时显示不可用及原因；默认运行实际使用 Kotlin，不提供假的 Rust 切换。只有 P3 实现后才接入真实的 Auto／Kotlin／Native 实验配置；切换在帧边界安全替换 session，失败遵守 native 设计的回退和释放契约。

诊断功能通过内部开发观察接口获取数据，不把内存句柄、JNI 指针或未稳定的调试类型扩散到公共组件 API。关闭面板时停止其统计 UI 更新。

## 8. 无障碍与视觉验证

图标按钮有文字说明和切换状态，交互目标按平台规范设置；不能直接照搬参考代码中较小的图标外框。键盘可进入进度、播放和设置，关闭面板后焦点回到入口。文字可读性、大字体和减少动态效果均纳入 Android／Desktop 验收。

准备窄屏、宽屏和大字体截图清单。每次截图记录场景、字体版本、viewport、density、fontScale、配置和时间；暂停后跳到检查点拍摄，再用连续录屏验证转场。默认系统字体适合日常演示；黄金对照采用单独选定且允许分发的固定字体，附来源与许可证，不能直接复制参考项目的 SF Pro 资源。

页面布局与操作方式对照现有示例；歌词视觉对照固定版本 Folia 原始仓库。两类验收分别记录，不能把原歌词列表当作 Folia 动画的视觉标准。

性能测量提供两种场景：完整示例界面，以及关闭背景和开发面板的歌词舞台。两者分别记录准备延迟、帧耗时、内存和平台能力；判断 Rust 收益时使用相同样本与条件，并计入跨语言成本。

- 原 Apache 工程无本任务造成的源码、配置、许可证或依赖变更。
- 在独立 checkout 中使用自己的 Gradle wrapper 构建，不需要原仓库或开发者绝对路径。
- Android／Windows x64 Desktop 均能打开内置场景；默认无网络、SPW、外部播放器或 Rust 环境也能运行。
- 窄屏与宽屏保留参考 UI 的信息层次，歌词区域实际使用 Folia 组件并正确响应约束变化。
- 暂停、恢复、点击、拖动、循环、倍速和切换场景使用同一时间语义；暂停 seek 后显示正确。
- 翻译／注音／减少动态效果可即时切换；没有对应内容时不保留虚假空白。
- 本地导入可成功、取消、失败和重载；旧请求不会覆盖后选内容。
- 页面不可见和关闭后没有无必要的时钟、采样任务或 native session 残留。
- 资源来源清楚；新示例自己的许可证与来源声明随独立项目交付。
- README 给出实际测试过的 Android 构建／安装与 Desktop 运行命令、JDK／SDK 要求、场景和限制。方案阶段不把尚未验证的任务名写成已通过命令。
